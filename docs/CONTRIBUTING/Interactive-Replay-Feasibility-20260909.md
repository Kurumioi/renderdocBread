# EID 检查点路线：有界保留与可行性评估

用户于 2026-09-09 要求重新判断检查点的收益、空间和跨平台成本，并决定停止扩大检查点
功能范围，修复现有问题后以有界、可回退的可选加速合入主分支。最终收尾和验收记录见
[收尾版本](EID-Bounded-Checkpoints-20260909.md)。下文保留作出该决定时的实验与门槛。

## 当前判断

真实资源检查点可以正确工作，但还未证明适合主验收捕获的实时交互。
不应继续以“补齐检查点必然会快”为前提扩张所有后端。优先保留有独立价值的 UI 修复、
合法向前增量、共享 Buffer 字节覆盖和差异恢复；大型检查点采用明确的投入停止门槛。

已有证据：

- Windows D3D11/D3D12/GL/GLES/Vulkan 的实际检查点、共享参数、Shader 替换/撤销正确性
  已有分开的 GPU 验收。尚无 Linux/Android/其他厂商设备的物理回归。
- GL/GLES 阶段恢复可沿用 1,800,000 B 上游内容，只复制 480,000 B；D3D12 CPU 写入
  fixture 的普通初值恢复从 2 MiB 降至 1–8 B。这些证明少搬数据，不证明整个交互足够快。
- v22 显式开启检查点的小 fixture，steady 阶段 SetFrameEvent 样本中位数如下。
  同一进程分阶段测量，GPU 与其他程序共享，样本有限；用于审视额外开销，不作为独占性能定论。

| fixture | 关闭检查点 | 开启检查点 | 检查点独占分配 |
|---|---:|---:|---:|
| D3D12 typed alias | 2.486 ms | 2.517 ms | 2,105,344 B |
| OpenGL 多阶段纹理 | 6.114 ms | 8.739 ms | 3,966,520 B |
| OpenGL ES 多阶段纹理 | 5.588 ms | 8.631 ms | 3,966,520 B |
| Vulkan 多阶段纹理 | 1.782 ms | 1.904 ms | 4,300,800 B |

因此小 fixture 的通过主要是正确性证据；不能拿命中次数或者省下的字节声称获得整体加速。

`1.rdc` v22 五次往返画面一致，未建成检查点。验收进程的 DXGI CurrentUsage 为
7,814,643,712 B，系统给它的 Budget 为 3,840,815,102 B；保护拒绝分配是合理结果。
稳态 722.68–1084.13 ms，不能与旧版不同显存竞争条件的时间直接比较。返回 24917 仍恢复
3,942,915,473 B，字节差异优化只省下 12,582,761 B。

旧版本曾保存约 489 MB 的 10535 检查点，仍额外恢复约 3.47 GB 初值，说明“检查点存在”
没有自动切断前面全部恢复成本。3.47/3.94 GB 是一次实际复制范围总量，不能直接当成
检查点额外占用；快照占用、原始资产占用、恢复流量必须分开记录。

## 最多再做一次有边界的验证

如果继续验证路线，先锁定同一构建、捕获和 EID 序列，对比关闭/开启检查点；其他优化一致。
选择一个已经证明合法、位置有利的阶段点，先建好，再测往返和固定 EID 调参。
分别记录预建时间、热切换时间、UI 输入至显示、额外独占/共享显存、实际恢复字节和完整画面。
受其他应用竞争导致无法分配时，该次实验只证明预算回退，不作检查点速度结论。

建议预先锁定的产品门槛（待实验，非已达到）：

- 大帧热切换至少达到基线 3 倍速度，同时 p95 不超过 50 ms；固定 EID 调参 p95 不超过 33 ms。
- 额外 GPU 备份优先不超过 256 MiB，硬上限 512 MiB；不接受靠数 GB 快照换交互。
- 除 `1.rdc` 外，至少另一种不同组织方式的捕获通过；生产策略不得包含 fixture 名称或 EID。
- 保持完整画面、共享参数与 Shader 撤销一致；未知访问回退。各 API 必须有同类测试，
  OS/设备覆盖单独列明，不把 Windows API 测试当成全平台完成。

如果有利阶段点仍不能明显减少主帧恢复与热延迟，就停止扩大通用检查点，保留轻量优化，
对特殊资源继续走正确的原始回放。只有实验达到门槛，才值得投入完整阶段依赖和更多后端优化。
两套完整工作资源目前增加显存、同步与版本维护负担，不作为绕过验证的下一步。

## 决策时源码状态及本版取舍

v22 后收尾包含有限空闲显存重试、可选状态与证据总量上限，以及默认预算与收益试用保护。
未统一验收的 typed inactive 初值省略实验已经从源码移除；保留 v22 已验证的 typed alias
检查点保存/恢复。不得将本版新修改混入 v22 验收结论。
完整逐 RT 的依赖传播和自动局部重建尚未生产接入；当前 Shader 保守全失效，CBuffer 根据
已证明的首次消费者保留之前检查点。这些限制应保留在后续决策中。

证据及逐项报告链接见 [v22 开发记录](Interactive-Replay-Resource-Versions-20260908.md)。
