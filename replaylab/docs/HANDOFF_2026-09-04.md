## 1. 已达到的目标

ReplayLab 不再维护自研 planner/reviewer/WorkflowGuard/工具收据式 Agent 运行时。现在只有两条执行路径，选择完全由连接类型决定，没有旧引擎开关或静默回退：

| 连接 | 固定执行路径 | Agent 形态 |
|---|---|---|
| Model API | `DeepAgentsEngine`，基于固定版本的 GitHub `deepagents` | deepagents 主 Agent + 按文件系统 Skill 生成的受限子 Agent |
| ACP / Codex 订阅 | `NativeAgentEngine` | 厂商 CLI 自己的单 Agent 循环；ACP 或 Codex app-server 直连任务级 ReplayLab MCP |

公共路径是：profile/凭据、冻结的 qrenderdoc 上下文、文件系统 Skills、Host 工具与效果权限、任务事件、报告表单和有界验收追问。两种引擎不共享一套自研推理循环。

## 3. 三层确定性约束

### 3.1 第 1 层：产物

HLSL、分析、流程图、导出清单等只能通过 Host 工具形成或进入项目。编译、ABI/有界输出观察、固定图形渲染、模板校验及逐项 verdict 都在确定性代码中完成。Shader 分析、模块和流程图使用 begin 返回的模板字段，Host 渲染样式；新 AI 调用不再走手写 Mermaid 旁路。严重错误不能靠用尽次数过关。

### 3.2 第 2 层：回答结构

`report_task_result` 已属于 MCP Host，规范实现是 `replaylab/mcp_host/src/task_report.py`；AgentHost 的 `agent_report.py` 只是薄导入层，不能复制出第二套校验逻辑。

报告 schema 为 `replaylab-task-report/v1`，包含：

- `summary` 与 `status`；
- 带 observed/inferred、置信度和工具证据的 `findings`；
- `artifacts`、`unknowns`、`next_steps`。

Host 验证 schema、observed 是否引用本任务实际调用的 Host 工具、inferred 置信度、产物路径和完成状态矛盾。工具名只证明调用来源，不自动证明每一句自然语言；有界、脱敏的结果摘要支持修报告和追溯。API 与原生路径共享任务 sidecar 的事实、报告和已用尝试数，重开同一 store 不能清零。

报告与 Shader 审核共用 `review_contract.py` 的 `replaylab-review-verdict/v1`：blocker 必须修正，warning 可注明后接受；原因含 code/location/direction/target/example。`REPLAYLAB_REVIEW_MAX_ROUNDS` 默认 3、范围 1–10，原报告变量 `REPLAYLAB_REPORT_MAX_ROUNDS` 和 `review.json` 设置作兼容回退。schema 错误计入预算，严重错误耗尽仍拒绝；这是内容审核次数，与 §3.3 的补交报告追问次数分开。

### 3.3 第 3 层：验收追问

所有后端都在一轮结束后调用同一 `ReportGate.verify()`。做过实际工作但没有已接受报告时，Host 生成自包含追问，其中包括原请求、上一版回答、已有 Host 事实/子任务结果、真实工具名以及精确的 `location + direction`：

| 后端 | 下一轮如何运行 |
|---|---|
| deepagents | 对同一个已编译 graph/Agent 实例再运行一轮 |
| ACP | 对同一个 ACP session 再发 `session/prompt` |
| Codex app-server | 启动新 thread；自包含追问携带继续所需的已有结果 |

`REPLAYLAB_VERIFY_MAX_ROUNDS` 默认 2、范围 0–5，0 关闭追问。耗尽时保留当前结果和 `verification` 原因，未完成不能标 completed；缺表本身是 partial，已有 failed 不会被覆盖。Codex 每个新 thread 重新带入原 system/核心 Skill 和有界 Host 事实；摘要缺内容时可做窄范围只读补充，不能重复已成功的副作用。

### 9.3 2026-09-05 Shader gate 与失败诊断修正

本轮按本文件决定重写了 `REBUILD_PLAN.md` §3.5 第 3 行的列职责，三条后端的接法保持不变。

- organization review 已支持 `exact-code` / `rename-only`，但原 publication 校验仍强制 code hash 相等，导致合法重命名审核通过后不能注册。本轮统一了可信发布和 server 结构校验，密封 equivalence/rename 证据，并在发布时重新证明实际源码的 rename-only 关系；没有取消当前 candidate/revision/source/ABI 的绑定。
- ABI 不兼容结果原先只返回调用者，manifest 仍为 pending。本轮新增 `lastAbiAttempt` 与 `abiValidationStatus`，将失败报告绑定到具体源码、revision 和候选；后续状态可区分 incompatible、source-changed 和未验证。新鲜失败撤销旧缓存 compatible，成功再验恢复；新编译不会继承旧失败。旧工作区需新鲜验证后才有失败记录，不能反推过去未保存的响应。
- 真实工作区只读证据仍表明动态 CBuffer、输入签名及资源类型恢复不足，本轮未修复反编译器、未应用实际替换。独立测试覆盖普通源码 hash 变化、重命名发布、失败报告篡改、旧证据过期及 compatible → incompatible → compatible。

详细证据、测试和后续顺序见 `SHADER_WORKSPACE_DIAGNOSIS_2026-09-05.md`。待办包括可编辑草稿入口与已审核发布分离、动态 DXIL ABI 恢复、softAccepted 的完整注册分支，以及 Codex 新 thread 的独立有界 Host 事实传递；不要把这些建议当作已完成能力。
