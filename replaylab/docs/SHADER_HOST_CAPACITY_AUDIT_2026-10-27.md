## 根因

1. 名称库按物理布局保存在一个 JSON 中。不同编译版本的显示映射不断累积，
   历史版本与新版本的数千字段挤在同一个 4 MiB 文件内。
2. 写前检查紧凑 JSON 的字节数，实际却使用缩进格式保存，导致通过预检的文件
   仍可能超过读取上限。失败后留下的旧格式暂存文件也可能妨碍同操作恢复。
3. 大工具结果的简要摘要可能丢失当前错误及可重试条件，甚至从嵌套历史中抽取
   成功状态。分页提示中的禁止重复调用也未明确限定为“不要为取回文本而重做操作”。

本次没有消息超限或 Provider 断连。单纯换模型、重复编译或缩短所有名称都不能
解决这次存储故障。

## 修复

- 大型语义字段改为内容哈希校验的不可变分页；每个布局的主文件只保存轻量索引。
  保留历史映射、用户命名及精确 Shader 范围，不清空旧数据来腾空间。
- 写前检查与实际写入使用同一序列化格式；旧缩进格式按已知格式兼容读取。
  分页先准备，索引原子提交；中断时沿用已有操作记录恢复和回滚。
- 当前窗口只加载匹配 Shader 的字段。历史版本不全部展开到内存；历史审查线索
  只读取相关的少量版本。缺页、哈希错误或无效用户字段不会被当成空数据覆盖。
- 大结果摘要只使用当前操作的状态，保留错误、操作 ID、终态和重试条件。
  完整证据仍可分页读取；支持修复后按回执重试，不自动重复有副作用的操作。
- API、ACP、Codex 共用上述 Host 与结果处理逻辑，没有只对某种连接打补丁。
- 原生编译根据捕获 API、源语言、原始编码、阶段、入口及目标版本选择路线。
  不支持的原生阶段会转交兼容的已注册编译器，不因前置原生调用抛错而阻断。
  编译成功仍须进行接口和输出检查；不支持的替换范围不会冒充已支持。
- Shader 整理规范删去重复说明，确保核心要求一次完整交付：新任务完整读取、
  按计算职责组织、先整理再审查、按失败层恢复。工作文件后缀跟随真实源语言。
- 编辑器注释取消斜体；规范要求使用通俗、具体的说明，不在注释中加入斜体标记。
