# 2026-10-20：EID 排序与部分材质语义复用

## 问题与修改

工作区原先按捕获、阶段分组，EID 在文件名末尾，不能跨阶段按数值浏览。现在同一捕获的着色器直接按 EID 数值升序排列，标签为 `EID 61523 · PS · MainPS · shader.hlsl`。多 EID 条目取最小值排序；无有效 EID 条目放在末尾。捕获及未保存工作副本仍分开，去重、项目最新源码身份、跳转与编辑保护保持原有逻辑。

资产调查的主要信息损失发生在 `propose_shader_names_from_asset`：旧输出的 material 摘要只有参数数量，未定位的参数名和值没有作为完整词典交给 Agent。当前版本增加 `materialSemanticContext`，保留解析出的标量、向量、纹理引用、参数元信息、位置候选和未定位参数。自动改名结果为空时，词典仍然可用。

Agent 使用三层信息整理代码：

1. 已确认的物理对应关系：具体绑定、偏移、分量及其来源，供源符号或资源面板命名。
2. 已关联材质的参数词典：名称、默认值或读取值、纹理引用，用来理解计算、设计函数职责和注释。
3. Agent 的计算推断：参考参数和实际源码数据流形成的用途解释、建议名，记录理由；不会自动变成已确认的物理映射。

`semantic_notes_json` 和 `links_json.materialHypotheses` 可在已有命名/关联工具调用中保存推断，无需新的一轮专用检查。整理仍按完整源码工作副本进行，参数语义在首次整理就参与函数划分与命名，随后做整体自检和最终编译、ABI、回放验证。

## 复用与成本

复用已有项目 resolution 数据库和工作区 `ai/asset-resolution.json`，没有新增第二套数据库。命名工具自动保存词典，并补充已有的项目关联记录。新对话优先读取本地记录；新 RDC 的工作区可对项目既有记录做一次原始 Shader 精确查找，不增加回放调用、整目录扫描或强制编译。

记录绑定项目、原始 Shader、阶段、入口、捕获/EID、材质及依赖内容指纹。换 EID、RDC、会话或平台后可以复用历史语义词典，但移除旧的物理位置候选并标记当前关联待核对；改变项目、原始 Shader、资产根或已核实的资产内容时不把旧词典当作当前结果。多个材质候选保留区别，不混成一个已经确认的材质。未主动重读资产时明确标注内容新鲜度未核对。

完整词典过大时保留到工具证据文件，聊天结果保留摘要和读取路径，不把截断词典伪装成完整集合。既有 resolution 数据库的 64 KiB 字符串截断也已修复：完整 JSON 有明确大小上限，历史损坏条目以诊断返回，不再导致整个读取失败。

## 边界

这是引擎无关的语义资料格式；具体资产格式仍依赖可用读取器。少量有辨识度的纹理/网格锚点及其依赖关系即可建立有用的材质关联，无需匹配全部纹理或常量。常见的 0、1、重复默认值或相同 shader 的不同材质实例不能唯一决定字段位置，需要结合当前源码运算、实际捕获布局和关系证据判断。

本次没有重新整理或覆盖用户的 Shader 源码，也没有把历史待验证稿标为已通过。变更作用于后续整理及跨对话/捕获的资料复用。
