# Repairing a missing execution capability

The Agent chooses the recovery method. A planner enumerates installed routes;
it does not prove that other implementations are impossible. Distinguish an
actual external limit from a missing adapter, metadata bug, compiler flag,
reflection parser, stale registration or ordinary source error.

For a Shader failure, `get_shader_repair_context` locates the original bytes,
saved source, current target, owner tool/route configuration and readable bridge
source without compiling or replaying. Discover its schema only if needed.
Native file/shell tools or the enabled portable execution MCP can inspect files,
write a small diagnostic/parser/adapter and run the supplied Python/Node or
compiler executables. File access and execution still use the connection's
existing permissions; neither this guide nor the context tool grants them.

Prefer a minimal tested repair in the current task's working directory. A
compiler adapter can be registered through the existing hash-pinned tool/route
configuration; inspect its actual schema, retain a backup, pin scripts and
executable dependencies, and validate before publication. The Host reloads
changed configuration by content fingerprint. Refresh only the affected saved
source's compile binding with `migrate_shader_workspace_toolchain(in_place=true)`
when that binding changed. Preserve the source and its history. Avoid changing
shared configuration under another running instance; a process owner can select
private configuration paths with the documented startup environment.

A parser or bridge source edit must actually be loaded before it can repair a
live operation. Test a staged adapter or isolated replay first. Do not overwrite
live native binaries or restart another user's application to make a patch take
effect. A native-core fix needs its real source, compiler and compatible binary;
if those are unavailable, investigate a supported alternate route and preserve
the concrete patch/diagnostic instead of pretending the running program changed.

After the diagnosed condition changes, run the affected compile/reflection and
replacement path and inspect the requested outputs. Preserve exact original
bindings, storage sizes, resource strides and evidence provenance. Missing type
annotations may be recovered as explicitly opaque physical envelopes from raw
declarations, not guessed source types. An original-bytecode passthrough does
not prove a rewritten Shader. Successful compilation or ABI compatibility does
not prove matching pixels.

Retain observations and successful artifacts by their actual inputs. Repeating
an unchanged failed attempt is not progress. Investigate another feasible cause
or method when it can resolve the gap; do not stop merely because a counter
expired. Ask the user only for an indispensable external input/grant or a real
remaining fidelity choice after feasible autonomous recovery. State exactly
what remains uncertain and what was tried. Respect an explicit pause immediately.
